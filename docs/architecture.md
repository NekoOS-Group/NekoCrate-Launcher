# 原型架构

## 边界

UI 通过单个带标签的 IPC Request 枚举调用 Rust。所有文件路径、实例 ID、版本解析、凭据及进程生命周期由核心处理。CLI 复用相同核心。前端维护视图、当前会话任务和本次启动器会话的日志，日志不再按固定条数截断。

核心模块：

- `auth`：微软设备授权、Xbox/Minecraft 令牌交换、权益检查与系统凭据存储。
- `skin`：提取 Minecraft 档案中的活动皮肤，限制官方纹理地址、文件大小与 PNG 尺寸，缓存公开纹理；请求不携带账户令牌，不跟随重定向。
- `download`：有界并发、逐来源重试、取消、哈希验证、内容寻址缓存、临时文件提交。
- `diagnostics`：持久化启动器操作失败，记录带时区的系统时间、版本、平台和脱敏错误链；单文件约 1 MiB，保留三份轮转文件。Minecraft 进程输出仍使用原来的游戏日志。
- `minecraft`：官方版本元数据、OS/架构/feature 规则、资源与库安装、原生文件解压、参数展开。
- `java`：运行时发现、主版本检查、Adoptium 下载与归档提取。
- `storage`：数据库保存、路径约束、实例文件复制、账户配置排除。
- `Launcher`：操作协调、隔离实例、账户元信息、游戏进程与日志。

游戏进程使用独立的 `LaunchSession`：微软会话转换为带认证参数的启动身份；没有选中账户时生成固定的 Player 本地身份，不持久化伪账户或调用身份服务。前端与 CLI 复用同一个分支。只有真实访问令牌和刷新令牌进入日志脱敏列表，本地启动的占位值 `0` 不参与替换。

## 数据

```text
<data-root>/
  database.json              设置、实例、公开账户档案；无令牌
  database.json.bak          上一次元数据快照
  launcher.lock              跨进程独占锁
  logs/launcher.log          更新、下载、启动与认证失败诊断；包含系统时间，敏感字段脱敏
  metadata/                 官方 manifest 与带校验的版本 JSON
  cache/objects/sha1|sha256/ 可验证内容缓存
  cache/verified-files.json 已验证文件的哈希、大小、时间与文件身份记录
  cache/skins/              按纹理标识缓存的公开玩家皮肤
  libraries/                仅兼容旧版本留下的依赖，新安装写入游戏目录
  assets/                   仅兼容旧版本留下的资源，新安装写入游戏目录
  runtimes/                 托管 Java
  instances/<uuid>/
    .minecraft/             仅托管实例；关联实例的游戏目录留在外部原路径
      saves/ mods/ config/
      libraries/ assets/    游戏依赖、资源索引与对象、日志配置
      versions/<version>/   同一目录可容纳多个版本
        <version>.json      此版本的官方元数据
        <version>.jar       此版本的客户端
        natives/            此版本的原生库
        runtime.json        运行时路径与版本（非凭据）
    launcher-logs/          脱敏的游戏输出
  trash/                    移除的托管实例，或外部实例的关联元信息与日志
```

实例身份使用 UUID，与名称分离。一个实例就是一个 `.minecraft` 游戏目录，包含 `versions[]` 与 `selected_version`；添加版本不创建新的游戏目录。多个版本共用该目录的存档、模组和配置，客户端与原生库按版本分别存放。运行中的实例不可切换版本，也不能同时启动第二个版本。

`game_directory` 为空时使用 `instances/<uuid>/.minecraft`；导入已有目录时保存规范化后的绝对路径，数据目录只保存实例元信息、日志及下载缓存、托管 Java。安装和修复将 libraries、assets、客户端与原生库写入所关联的 `.minecraft`，启动参数优先使用同一目录的资源与依赖；旧版本留在应用目录的资源仅作为兼容读取，不再作为新安装的目标。`Instance::game_dir` 统一决定启动工作目录、`--gameDir`、客户端与原生库路径，安装与目录打开也使用这一位置。导入不遍历复制游戏树、不读取其他启动器凭据；拒绝重复、嵌套关联和与启动器数据目录重叠的路径。原路径不可用时启动、安装、复制会报错，不在原位置自动重建空目录。移除关联实例只归档启动器自己的元信息／日志，原目录保持原处。

文件夹拖入使用 Tauri 原生 `onDragDropEvent`，由 `useFolderDrop` 管理扫描、批量预览与关联。`folder_import` 在阻塞工作线程中只读遍历目录，包含隐藏项；输入根路径规范化去重，不跟随下层符号链接，识别到游戏目录后不再进入其内部，跳过启动器数据目录。候选项包含父文件夹默认名称、原路径和所有子版本；已有实例保留现名并标记为已关联。`scan_folders` / `cancel_folder_scan` 使用独立取消令牌，不占用或取消下载任务，前端忽略已取消或被替代扫描的迟到结果。`import_folders` 在提交时重新检查目录与重叠关系，逐项返回成功和失败，仅写入关联元数据；扫描状态在右上角展示，可直接取消；未找到目录时在右上角显示“未找到实例”，2 秒消失。单个新目录自动关联，整个过程不挂载中间弹窗；只有多个目录才打开勾选列表。成功提示显示“已关联实例 名称: 路径”，2 秒自动消失；失败仍通过主界面错误提示展示。手动导入不填名称时也采用解析后的游戏目录父文件夹名。

实例元数据的可选 `icon` 保存 16 种内置图标的编号，缺失时沿用 UUID 决定的原四款默认图标，兼容已有数据库。 草方块、冰块和红砖使用 MC 1.21.1 原版贴图；编号 6 的竹板替换为史莱姆方块，编号 8 的深板岩砖替换为工作台，保持保存的编号与目录顺序不变。草顶和侧面草层在 SVG 中按原版默认草色乘色，工作台使用独立顶面／侧面／正面，史莱姆保留原始透明度并按游戏模型绘制 3–13 像素的内部方块；图标文件来源及哈希记录于 `app/src/assets/blocks/provenance.json`。`InstanceHeader` 在实例弹窗标题栏提供图标选择、名称原位编辑和目录链接；名称与图标随表单保存，取消不修改实例。目录通过只读 IPC 获取实际路径，点击时复用系统文件管理器打开流程；改名和换图标不会移动游戏目录。图标选项以轻微位移／缩放与错峰渐显展开，关闭时退场并立即停止接受输入，当前图标采用同位置交叉淡入淡出，保持标题布局稳定。主题与图标的鼠标选择不强制移回焦点；键盘选择和 Esc 返回触发按钮，常规配色下用图形发光表达焦点，强制对比色模式保留焦点轮廓。

实例 Java 使用下拉列表：自动匹配、探测到的本机／托管 Java、手动选择过或已用于实例的路径。进入实例设置时异步探测，结果按版本降序去重，不覆盖当前选择；探测失败仍可使用自动或文件选择。末项通过系统文件选择器指定可执行文件，取消或旧弹窗的迟到结果不改变配置；自动选项保存为 `java_path: null`。Java 菜单向下展开，表单允许菜单溢出，菜单高度按窗口剩余空间限制，长列表内部滚动并保留文件选择入口。

实例顺序直接持久化为数据库 `instances` 数组顺序。拖动图标使用 Pointer Events 与指针捕获，移动超过 6px 才开始排序，支持边缘自动滚动、Esc／失焦取消和 Alt＋左右方向键排序；松手后抑制误触选择。拖拽期间通过 `TransitionGroup` 预览位置，相邻图标以 320ms 先快后慢曲线让位，命中判断使用布局坐标以避免动画造成抖动；开始移动时把指针捕获转移到稳定的滚动容器。拖动预览保留原图标的透明度与发光；松手后以 360ms 动画归位，再交叉淡化到真实图标；保存回滚时从动画当前位置改道。`move_instance` IPC 仅提交来源与目标位置，不覆盖整份实例列表；数据库锁内按 ID 移动，拒绝已删除的来源或目标，允许运行／下载期间排序。保存失败恢复原排列，当前选择、游戏目录、版本状态和游戏进程不变。 拖动已有实例时右上角出现无外框垃圾桶，72px 命中区与图标动效分离；单实例也支持拖动。松手放入有效区域后按 ID 调用已有 `delete`，仅在提交成功后从列表移除，保留拖动副本完成缩小淡出；失败则按原归位动效返回。运行或任务处理中不允许拖拽移除，Esc、失焦、失去指针捕获和放到其他区域均不触发删除。关联目录仍留在原处，托管实例沿用移至回收目录的语义。

CLI 显式复制实例时才复制整个游戏目录和版本列表到新的托管目录，保留已安装状态，目录内的资源与依赖一起复制，后续下载复用内容缓存；复制过程不跟随符号链接，并排除已知启动器账户文件。导入只关联来源并识别多个独立版本 JSON，首次启动前仍须校验安装。

数据库 schema 3 支持目录关联。schema 1 仍先迁移旧的一对一实例：将 `game/` 改为 `.minecraft/`，把旧版本纳入版本列表，迁移元数据、客户端和原生库；迁移前保存 `database.v1.json`。schema 2 升级时保存 `database.v2.json`，已有托管实例和以前导入的副本不移动、不推断来源；旧格式未记录来源，不通过猜测自动迁移。可以先核对并补齐原目录缺少的新增文件，再使用 CLI `relink <实例ID> <原目录>` 原位切换关联；它保留实例 ID、名称、图标、配置和匹配版本的安装状态，校验原来已安装的版本 JSON/JAR 与目标一致，拒绝漏失版本和重复／嵌套目录，保存 `directory-link-before.json`，不复制、移动或删除任一游戏树。旧客户端会拒绝 schema 3，避免忽略关联路径后误用空的托管目录。

账户档案新增可选的 `skin` 元信息（URL、是否纤细手臂），旧账户反序列化默认为空，刷新账户后补齐。前端经 IPC 获取纹理字节，使用 [skinview3d](https://github.com/bs-community/skinview3d) 进行透明背景的 WebGL 渲染，并从同一纹理裁切头像；不开放 WebView 对外纹理请求。切换账户时丢弃过期请求结果，关闭组件释放渲染资源，弹窗打开或窗口不可见时暂停绘制。未登录、无皮肤资料或加载失败时回退到内置的原版 Steve 纹理；加载失败保留重试入口。

皮肤场景使用按需绘制：纹理、尺寸、视角改变时合并到下一显示帧，OrbitControls 惯性未结束时继续更新，静止后停止 WebGL 重绘。隐藏、弹窗与 WebGL 上下文丢失时取消待绘制帧，恢复后补绘；像素比、抗锯齿、灯光、模型与拖动参数保持不变。背景动画独立运行。皮肤画布的键盘焦点使用沿透明角色轮廓的白色硬边描边，替代矩形焦点框；只在 `:focus-visible` 时通过 CSS 合成，不增加 WebGL 绘制循环。`rendering.test.mjs` 覆盖静止、合并请求、惯性、暂停恢复与销毁。

主界面使用左上账户卡片、底部主题与实例图标、分体启动按钮。账户卡片打开头像选择弹窗，点击头像选择当前账户，「+」进入添加流程；非当前账户头像独立加载官方皮肤，并忽略已卸载组件的异步结果。登录应用配置归入添加账户流程，保存全局设置时保留最新应用编号。`GlassDialog` 基于原生 `dialog.showModal()` 实现焦点约束和背景隔离，初始焦点放在静态标题上，账户、设置、日志、下载与实例管理复用该弹窗。`VersionMenu` 在启动按钮旁向上展开当前实例版本，尾项进入下载弹窗；菜单独立处理键盘导航、Esc、焦点离开和外部点击收起，切换实例会收起旧菜单，保留版本按钮节点以避免闪烁。五套主题由统一 CSS 变量驱动，主题与当前实例选择在本地持久化。主题图形的可见大小与间距不变，真实透明按钮连续覆盖 36 × 64px（当前主题为 44 × 64px）；命中区不随展开动画移动，按下时捕获指针，松手后提交选择，避免 Safari 失焦收起菜单。主题区域高于实例列，防止选项被后绘制的实例按钮遮挡。默认与最小窗口均为 900 × 600。

`flowGraph.ts` 在整数周期格点上构造蜂巢、大小方块、菱形、三角和八边形／小菱形五种平面铺砌，共享边只保存一次状态。`hexFlow.ts` 保留既有模拟 API，统一使用图中的邻边数量计算转移概率；封闭面识别、容量及染料交换适用于所有图形。`WorldBackdrop` 用常驻 GPU 的有序几何批量绘制，不逐帧触发组件重渲染；整张图的状态始终推进，呈现时由 GPU 裁切不可见区域。切换主题时通过组件 key 清理旧动画帧、尺寸监听和可见性监听，再构造新图形。弹窗和菜单不暂停背景；隐藏页面、减少动态效果和高对比模式分别停帧或隐藏装饰。

背景复用连通区域遍历队列、标记及染料来源缓冲区。`flowPainter` 保留原有阈值、精度与混色比例，普通数值直接舍入，半边界回退到原 `toFixed` 转换以保持结果。`flowGeometry` 将原路径编为有序几何，`flowWebGL` 每帧一次属性上传、一次实例化绘制，保持色块、边线和周期副本的透明叠加顺序；线宽的像素覆盖率在着色器中计算，不使用低分辨率画布。设备不支持所需 WebGL 能力时回退到直接绘制可见路径的 Canvas 2D。上下文丢失时停帧、恢复时重建资源，恢复失败使用 2D 回退。五套主题的模拟哈希及逐帧绘制数值与旧 SVG 对照，离屏栅格验证覆盖 DPR 1、1.25、2 与周期接缝；具体证据和复现方法见 `docs/performance/dev0.4.md`。空实例的主按钮合并右侧菜单区域，直接打开版本下载；已有但未下载的子实例显示「下载并启动游戏」，沿用安装成功后启动的流程，切换已安装／待下载版本时只过渡内容、不改变按钮宽度；已有版本时启动图标与文字成组上移 5px，版本号在整组下方居中。账户栏、启动按钮和上拉菜单共享透明底色，启动按钮悬停与账户栏使用相同透明度。启动区固定外宽，启动／下载状态仅通过内容移位、交叉淡入淡出和版本按钮浮现过渡；子版本名独立做轻微移位与淡化，短暂保存状态不改变按钮透明度。

全局设置标题栏直接展示「通用设置／网络设置／关于」页签，支持方向键、Home／End 切换。初始焦点仍放在静态容器上。通用页提供语言、游戏启动时跟随语言的开关、启动器版本与更新状态，以及启动器目录；网络页包含游戏本体与 Mod 下载源、系统／直连／手动代理、并发数与自适应开关；失败重试参数保留在后台，不再显示于设置页。关于页采用居中图标、名称与版本小字、版权／许可行及图标链接的纵向布局；源码与问题反馈入口居中并排，许可证标注 GPL-3.0，仓库代码采用 GPL-3.0-only，第三方素材保留原权利声明；不再展示 Java 检测、自动安装 Java 开关或下载记录入口。所有可编辑项修改后立即生效并自动持久化，不再提供取消／保存按钮。数字输入逐字段校验，空值或越界时保留编辑内容并提示，不阻止其他合法选项生效；关闭再打开恢复最后有效值。保存失败保留修改并提供重试入口。`GlassSelect` 为语言、下载源和 Java 复用主题色玻璃菜单；`DownloadSourceSelect` 分别展示游戏和 Mod 来源，各有自动选择，不再使用“优先”策略文案；选择项支持方向键、Home／End、Enter、Esc、焦点离开和外部点击，组件卸载时清理监听。菜单悬停只改变文字和光效，不使用渐变填充；版本菜单选中项通过文字光效与六边形饼图标识：已安装显示满格，待下载的非选中项使用虚线方块。任务按实例 ID 与版本 ID 绑定，饼图按游戏文件的字节比例表达近似进度，已校验的目标文件／缓存和可续传部分都计入；阶段切换和取消不清零，未确认安装完成前最多显示 99%。每个子实例保存 `download_progress`，运行中最多每秒持久化一次，取消／失败时补写最后进度。已有持久化进度直接用于展示；仅对缺少进度的未完成版本，首次快照异步从校验过的本地元数据与资源索引重建清单，通过文件大小盘点回填旧任务进度，完成后通知前端刷新；盘点不读取游戏文件内容、不建立校验记录，实际续传会纠正失效数据。不请求网络、不修改游戏文件、不等待扫描才展示界面，同一进程每个版本只扫描一次。新任务继承磁盘／会话进度，旧的零进度任务不能遮盖恢复结果。菜单在下载期间可只读展开，切换和添加版本暂时禁用。饼图采用 SVG 等面积分区并以短暂缓动过渡，减少动态效果时直接更新。


语言支持「跟随系统 / 简体中文 / English」，默认跟随系统。系统首选语言由 Rust `sys-locale` 读取并随快照传入前端；简体中文使用中文，其他语言（包括繁体中文）使用英语。设置中的语言即时应用并保存，关闭弹窗不会回退。文案、菜单、无障碍标签和启动器提示在前端本地化，用户名称、路径和游戏原始日志不翻译。语言标签复用实例字段的 12px 字体与 44px 控件；「启动器版本」使用同样的小标签，当前版本号与「启动器目录」同为 14px。设置页签交叉切换时保留内容区高度；弹窗打开／关闭使用淡化和轻微缩放，关闭完成后退出顶层模态并恢复原焦点，切换到另一弹窗时不会抢走新弹窗焦点。背景动画独立继续运行。

开启「游戏启动时跟随」后，启动前按同一解析规则把 `options.txt` 的 `lang` 设置为 `zh_cn` 或 `en_us`。关闭时不触碰此文件；开启时保留其他选项及换行格式，原子写入并备份为 `options.txt.nekocrate.bak`，内容未变时不轮换备份。旧数据库缺少新增字段时兼容默认设置。 开关通过 `aria-labelledby` 获取名称，文字和整行不代理点击，仅开关本体可切换。

打开设置时从官方仓库 GitHub Releases API 检查更新，识别紧凑 dev 标签与语义版本；开发版接受预发布，稳定版只接受稳定发布，不降级。安装后的 macOS / Windows 与 Linux AppImage 使用所选发布下的 `latest.json`，通过 Rust 端 Tauri updater 下载、验签、安装与重启。更新清单及安装包 URL 固定在当前仓库、当前标签，公钥内嵌并启用 `requireSignedVersion`。网络沿用系统／直连／HTTP／SOCKS 和代理认证，进度最多约每 100 ms 推送一次，与游戏任务列表分离。

下载支持取消，验证后的包暂存在内存；关闭设置弹窗不影响下载，前端重载可恢复后端状态，退出程序则需重新下载。空闲时下载完成自动安装并重启；有运行中的游戏或任务时显示「安装并重启」，服务端重新取得任务互斥锁并检查游戏状态后才能安装。安装失败保留包供重试，安装期间拒绝新操作；重启前释放数据目录锁，避免新旧进程短暂重叠导致目录占用错误。Windows 由 NSIS updater 完成退出和重新启动，macOS/Linux 使用 Tauri 重启。DEB、开发模式、未安装的 macOS 二进制以及没有更新清单的旧发布使用明确标注的手动安装入口。

全局设置保存独立于下载任务的忙碌状态，并由数据库锁原子持久化；正在执行的下载保留任务开始时的配置，新任务等待尚未完成的设置写入后再开始。连续修改按字段记录修订并串行合并写入，写入时控件保持可用，与登录应用编号的写入互相等待以防覆盖。下载完成只刷新状态，不重置正在编辑的设置或页签。快照请求采用顺序编号，同时保留待保存字段，避免旧快照覆盖新设置；关闭弹窗不取消写入，完成后也不会关闭后来打开的弹窗。

应用图标使用 AI 生成的 Minecraft 像素猫咪盒子、Creeper 与浅浅探头的 Minecraft 猫猫，原图及完整提示词保存在 `app/src/assets/neko-cat.png` 和 `neko-cat.provenance.json`，通过 Tauri icon CLI 生成 PNG / ICO / ICNS。

## 一致性与恢复

元数据操作在互斥锁中执行，先保存候选数据库再更新内存。安装通过版本解析后、修改游戏文件前，才将所选版本的 `installed` 设为 false；全部文件和 Java 就绪后才设为 true，不影响同实例中的其他版本。版本不支持或元数据获取失败不改变原有安装状态。运行中的实例禁止复制、修改、移除、重装。

下载文件只有在哈希与大小验证通过后才晋升为完整缓存／目标文件。未完成的网络数据保存在按内容哈希命名的固定 `.part` 路径，取消、网络错误和重启后保留；下次发送 HTTP Range 请求，核对响应区间与总大小。服务器忽略 Range 时从零覆盖，416 时重试完整请求；范围错误或最终哈希不符时丢弃该部分，绝不拼接错误响应。目标目录内的临时复制文件仍在取消／错误后清理。批量下载先盘点已有字节，再按有界并发逐文件检查与下载，缺失项不再等待全队列哈希校验。聚合进度包括完整缓存与已接收字节，不受文件排序影响。同一缓存对象并发请求串行，缓存复制到目标，避免用户修改目标文件破坏缓存。每个网络来源有独立重试，身份服务请求不走文件镜像。

版本解析先检查本地版本 JSON 中的继承关系、加载器主类／库和旧启动协议，明确不支持时在创建网络客户端之前返回，不根据实例名猜测加载器。缺失或损坏的本地 JSON 仍可通过官方元数据修复。官方完整目录保存在 `metadata/manifest.json`：正向命中不受缓存年龄限制，直接按目录中的哈希校验／获取版本 JSON；15 分钟内的完整目录未命中也直接返回。只有缓存缺失、损坏或超过 15 分钟且未命中时才联网刷新，刷新失败保留网络错误，不把它误报为版本不存在。版本选择页的手动同步仍可立即更新目录。

实例名称、图标、内存和 Java 路径的保存只使用数据库锁，不等待下载操作锁，不覆盖版本状态；正在下载的任务使用开始时的配置快照。前端按实例 ID 防止重复保存，用弹窗会话编号隔离迟到响应，其他实例的编辑、保存和关闭不受任务忙碌状态影响。双击下载中的实例进入当前任务流程，其余实例仍打开设置。

下载面板显示单个当前／最近任务，预先列出版本解析、文件下载校验、原生库、Java、完成安装五个阶段；启动任务使用独立的启动阶段。`workflow` 事件推进阶段，`file_plan` 批量登记文件，`file` 更新每个目标路径的字节数和状态；事件统一携带实例 ID 与阶段，排除无关实例事件。只有通过文件校验才标记完成，失败／取消保留已完成阶段和已接收字节，后续阶段显示未执行。逐文件列表采用虚拟滚动，一次最多渲染 10 行；按阶段维护稳定的下载中／其他文件分区，通过 Fenwick 索引在状态变化时更新一个位置、按排名获取可见行，避免每次扫描全部文件。高频文件进度不写入日志；日志存入非响应式追加缓冲，窗口关闭时不发送界面通知，打开时每 50ms 合并刷新一次，不逐条触发整个主界面更新。新任务释放旧任务文件明细，保留用于版本进度图标的摘要。

恢复下载时先用文件大小盘点目标、内容缓存和断点文件，再以已有字节初始化队列与总进度；这些文件仍处于等待／校验状态，命中有效校验记录或重新计算哈希通过后才标为完成。文件阶段显示字节进度，悬停可查看本次已校验数量，避免把从零开始的校验计数误当成重新下载。磁盘盘点或校验发现数据失效时，通过 `reset_progress` 同步纠正任务、版本图标和持久化进度；普通阶段切换不清零。缓存命中显示「已缓存」，下载源拒绝或忽略续传时记录对应文件的重下原因。版本菜单右侧统一显示「待下载」，进度继续由图标表达。

下载面板的暂停／继续、取消与关闭位于固定标题栏，流程和文件列表独立滚动。下载列表将正在传输的文件稳定排列在最前，其余文件保持原顺序；单纯字节变化不触发排序。暂停通过 watch 信号停止轮询同一个安装 Future，保留阶段、队列与已接收数据，继续时恢复原操作；取消在暂停时仍能执行清理与最终进度保存。前端暂停控制独立防重复请求，下载完成后仍执行原有的自动启动动作，不重新创建安装任务。

操作错误统一通过窗口右上角的 `ErrorNotice` 展示，不在设置、下载和实例弹窗内容区重复显示。`dialogSurface` 跟踪原生 modal 顶层，将同一通知移到当前 dialog 的面板外，关闭弹窗后返回主界面；支持关闭错误提示和重试设置保存。下载失败仍在流程中标记失败阶段，错误正文只显示在右上角。

## 后续扩展点

加载器应在版本解析/安装计划层加入，不在 UI 中拼启动命令。整合包更新应提供独立的文件清单、差异计划和回滚协议。外置认证应实现独立提供方，不改变微软权益验证语义。

本原型未提供任意启动前 shell 命令。已有目录中的启动配置作为用户选择的本地配置读取，支持原版、Fabric、Forge、NeoForge；不执行 shell 字符串。原版安装仍通过官方目录校验元数据，Fabric 安装使用官方 Meta API，Forge / NeoForge 从官方仓库取得并校验安装器，解析客户端处理步骤，以独立参数启动 Java，不执行 shell 字符串。

`version.rs` 递归解析 `inheritsFrom`（限制深度并拒绝循环及越界路径），合并参数、依赖、下载与日志配置，保留客户端 JAR 所属的基础版本；按 Maven 坐标补全旧版与 Fabric 依赖路径。HMCL 合并后的 JSON 直接读取，不重复应用 patches；额外识别 `primary_jar_name`、游戏版本标注和原隔离工作目录。发现版本时快速检查启动文件，启动前再次检查并解压本平台 natives；关联、扫描和解析不改写原版本 JSON。

`fabric.rs` 获取游戏版本对应的加载器列表并缓存一小时，下载官方 profile；缺少 SHA-1 的依赖通过对应 Maven sidecar 获取校验值，再交给已有下载、校验和内容缓存。基础版本 JSON/JAR 保持独立，Fabric profile 保留继承关系；安装、暂停、恢复、修复沿用同一文件计划。已安装 Forge / NeoForge 直接解析本地配置，不在官方目录中搜索整合包名。

`loader/installer.rs` 提供普通版本与整合包共用的安装核心；输入基础游戏版本、加载器及目标 ID，不依赖整合包对象。旧 Forge 从安装器提取通用 JAR，现代 Forge / NeoForge 执行客户端 processors 并校验声明的输出。处理器只需的原版 client JAR 单独下载；资源及完整游戏依赖在生成加载器配置后统一安装。只有全部成功才发布最终版本 JSON。

`loader/mod.rs` 将普通加载器安装选择、完成状态和进度保存在目标版本的 `.nekocrate/loader.json`，扫描与关联目录时可恢复未完成版本；新建版本建立独立的 `mods/config/saves`。同名且没有匹配安装记录的目录拒绝覆盖。暂停通知通过任务局部上下文传给处理器监控任务，即使外围下载 future 暂停轮询，Java 子进程仍会被终止；恢复时仅重新执行被打断的步骤。普通网络传输仍保留原 future 和续传状态。安装输出的 `overall_progress` 与文件字节进度独立，避免单个阶段结束令整体进度提前达到 100%。

`loader/catalog.rs` 使用 Forge 的 [Maven 目录](https://files.minecraftforge.net/net/minecraftforge/forge/maven-metadata.json)和 [promotions](https://files.minecraftforge.net/net/minecraftforge/forge/promotions_slim.json)，以及 NeoForged Maven 的公开版本接口（`/api/maven/versions/releases/net/neoforged/neoforge`，1.20.1 使用 `net/neoforged/forge`）。保留 Forge 分支后缀；NeoForge 分别处理旧编号、26.x 的补丁编号和快照后缀，安装时再核对安装器内的 Minecraft 版本。目录磁盘缓存一小时，刷新失败可复用旧目录，取消不回退为成功。前端 `loaderCatalog.ts` 按游戏版本与加载器缓存列表、合并相同请求、记住本次会话的选择；过期列表保持显示，在后台刷新。


Java 自动匹配考虑版本、架构与模组约束：旧 macOS Intel natives 使用 x86_64 Java；现代加载器自动选择完整 JDK。精简 Temurin JRE 的 Java 类缺少局部变量表，会使 Preloading Tricks 3.5.6 的 ResolverTransformer 失败，因此不用于现代加载器自动匹配。`java_compatibility.rs` 使用版本配置的 `compatibleJavaMajors` 或明确核实的加载器范围，结合 ASM 字节码上限、Fabric/Forge/NeoForge 模组的 Java 约束以及嵌套 JAR 检查，优先复用兼容范围内最高版本的本地 Java；确实需要下载时才选择该范围的最高版本。检查在后台执行，以文件路径、大小和修改时间缓存模组结果，并限制嵌套层数及解压总量。最低版本声明本身不证明支持任意更新 JVM，模组信息不完整或依赖覆盖尚未解析时退回游戏声明版本。现有核实规则范围有限，不能保证任意整合包都能跨 Java 主版本。手动指定路径也会拒绝超过已知 ASM/LaunchWrapper 上限的 Java；旧 LaunchWrapper 保持 Java 8。

`memory.rs` 集中计算内存，实例持久化 `memory_mode=auto/recommended/minimum/custom`，`memory_mb` 只保存自定义值。新建、导入及缺失模式字段的旧实例默认 Auto，复制保留原模式；切换模式不覆盖自定义数值。Auto 在启动前通过 sysinfo 仅采集 RAM，参考 [HMCL 的可用内存曲线](https://github.com/HMCL-dev/HMCL/blob/main/HMCL/src/main/java/org/jackhuang/hmcl/game/HMCLGameRepository.java#L465-L480)：预留 512 MiB、前 8 GiB 取 80%、剩余部分取 20%，限制为 512–16384 MiB；系统读数不可用时使用不超过 4096 MiB 的推荐值。32 位 Java 自动值最多 768 MiB；其他模式超过 1536 MiB 时提示切换 64 位 Java，避免静默降低手动或整合包配置。

推荐／最小是本启动器的经验预设，不代表官方硬件要求或运行保证：原版 1.12 及之前为 2048／1024 MiB，其余为 4096／2048 MiB；有加载器的旧版为 4096／2048 MiB，现代版为 6144／3072 MiB。实际工作目录中有效 Mod JAR 数量达到 100、200、400 时分别采用 6144／4096、8192／6144、12288／8192 MiB；仅枚举该目录，不解压 Mod。读取 `mcbbs.packmeta` 和 HMCL `modpack.cfg` 内 `launchInfo.minMemory` 声明作为预设下限，不把其他启动器的个人 JVM 设置误当作整合包要求。预览只在打开实例设置时计算，启动前再计算，CLI 和桌面复用同一核心。最终生成唯一的 `-Xmx` 与 `-Xms256M`，清除导入参数中冲突的堆大小参数但不改写原 JSON。设置中最小／推荐显示估算数字，自动仅显示文字，自定义直接编辑数字，`MB` 显示在控件外；数值沿用 JVM 的 MiB 单位。

`runtime_compatibility.rs` 在启动时对已解析配置应用限定平台和版本的修复，不改写导入的版本 JSON、原依赖 JAR 或模组配置。macOS 上受影响的 JNA 5.8–5.12 升至 Mojang 1.20.2 所用的 5.13.0，修复长 `dlerror` 文本导致的原生断言退出。LWJGL 2.9.2-nightly-20140822 的已知 Intel macOS natives 使用 Mojang 校验过的 OpenAL Soft 1.23.0 替代解压目录中的旧音频库，解决 `AudioUnitInitialize` 失败后回退至无 EFX 系统实现、触发 Sound Filters 40962 错误的问题；LWJGL 图形库保持原版本，旧音频库保留备份。补充文件使用正常下载器，遵循代理、来源选择、缓存与哈希校验。

子实例菜单从解析后的 `minecraft_version` 和 `loader` 字段显示 `游戏版本 · 加载器 版本`，副标题为 10px。游戏进程结束后先排空 stdout/stderr，再发送退出事件；非零/异常退出且非主动停止时发送 `game_crash`，前端自动打开运行日志并滚动到最新诊断。

运行日志保留脱敏后的原始文本供复制；展示层按时间、级别、来源和正文排版，只移除正文开头重复的时间戳及终端控制序列。INFO/WARN/ERROR 等级单独着色，异常原因突出、栈帧保留缩进；同实例、同类型的相邻相同内容合并计数，顺序和原始条目不丢失。解析按原始条目弱引用缓存，新增批次只追加展示行，清空或切换语言时重建；日志窗口隐藏时不做展示计算。按实例、级别和正文／来源关键词筛选，搜索异常时保留相邻异常链；复制包含筛选后的原始条目，清空仅影响当前来源。列表按实测换行高度虚拟滚动，仅挂载可见行与邻近缓冲，但保留和检索本次会话的全部日志，不限制为 800 条。新日志跟随底部，读者向上滚动时保持阅读位置，支持返回最新日志。双击运行中实例直接打开并筛选该实例日志，崩溃时清除旧筛选并显示该实例最新诊断。


### 网络来源与代理

游戏源保留 `download_source` 字段以兼容旧配置，新增配置默认 `auto`；显式 `official` 或 `bmclapi` 只使用选定来源。自动模式在每个下载任务中按源域名并行探测响应头，采用最先成功的来源，探测限时 3 秒；同域名并发文件复用探测结果，失败时仍有重试与另一来源回退。只改写已知公共 Minecraft 域名，不改写登录、带凭据／查询参数或未知域名的 URL。

`mod_download_source` 独立保存为 `auto`、`modrinth`、`curseforge` 或 `bbsmc`；旧 `official` 选项显示为自动选择，并在下次保存时归一为 `auto`。这是资源平台选择，不会把 Modrinth 文件 URL 直接改写成 CurseForge 或 BBSMC 地址，也不受游戏本体镜像设置影响。本原型尚无 Mod 浏览／安装流程，目前完成平台选项、校验和持久化，尚未实现自动跨平台搜索和文件安装。

来源调研（2026-10-23）：[Modrinth](https://docs.modrinth.com/api/) 提供公开搜索、版本与文件信息；[CurseForge](https://docs.curseforge.com/rest-api/) 提供 Mod 和文件接口，需应用 API Key，且[官方公告](https://blog.curseforge.com/introducing-api-key-authentication-for-curseforge-file-downloads/)要求 CDN 下载也使用有效 Key；[BBSMC](https://bbsmc.net/) 是中文资源社区，其[官方仓库](https://github.com/bbsmc/app/tree/main/apps/docs)提供开发者文档与 API 规范。MC 百科更适合中文资料检索；GitHub Releases 属于按项目发布的来源，暂不作为统一 Mod 平台选项。MCIM 的[现行仓库](https://github.com/mcmod-info-mirror/mcim-rust-api)标注服务暂停及文件下载不可用，未列入选项。

代理以独立开关控制：关闭写入 `proxy_mode=none`；开启可选 `system`、`http`、`socks`，兼容旧 `custom` 配置并按地址识别协议。切换协议保留有效主机与端口，HTTP 选项支持 HTTP／HTTPS，SOCKS5 选项支持 SOCKS5／SOCKS5h；`proxy_url` 支持无账号密码的 HTTP、HTTPS、SOCKS5／SOCKS5h 地址（SOCKS 需显式端口）。reqwest 启用 system-proxy 与 socks 功能，统一构建下载、Java、登录、皮肤和更新客户端。手动地址结束编辑且校验通过后，与模式一起保存；未完成输入不覆盖有效设置，也不阻塞其他字段。当前下载保留开始时的设置快照，新请求采用最新设置。浏览器打开登录页及游戏自身联网仍由各自应用管理。

HTTP／SOCKS5 在下一行显示账号、密码，任一字段为空即不发送认证；HTTP 使用代理认证头，SOCKS5 使用用户名密码握手，不发送为目标服务器的 Authorization。用户名随设置保存，密码只保存在系统凭据存储，数据库只存不透明 UUID。`proxy_password` 是只写 IPC 字段（缺省保留、空字符串清除），不会出现在 JSON、备份或 Debug 输出中；弹窗通过单独 RPC 恢复遮罩输入值。新密码先写入独立凭据项，再提交数据库；失败清理新项并保留旧项。读取失败、过期读取回包及其他设置的自动保存都不能误清空或覆盖密码。

游戏源、Mod 源和代理类型菜单 Teleport 到所属原生 dialog 中，与设置框平级，避免被面板的滚动和高度动画裁切，也不会掉到原生 modal 的背景层。仅展开时逐帧跟随触发按钮，保留窗口边距及长菜单滚动；点击外部、键盘焦点离开或卸载后清理跟踪。设置框和选项列表隐藏横纵滚动条，超出窗口时仍可滚动，不因高度过渡出现滚动条闪烁或挤占布局。

### 皮肤键盘高亮

参考 Minecraft Java 1.21.1 客户端中 `shaders/post/entity_outline.json` 的离屏描边流程及 `shaders/program/entity_sobel.fsh` 的透明度边缘识别思路，实现独立编写的 `skinOutline.ts`，未复制原版着色器代码。轮廓 pass 接在 skinview3d 的 FXAA 后，采样角色透明度向外扩展约 1.6 CSS 像素的白色轮廓，保留内部色彩和透明背景；没有矩形焦点框或 CSS 阴影。焦点、失焦和输入方式切换会显式触发按需重绘，静止时不新增连续渲染。尺寸与 DPR 变化更新采样步长，卸载时移除 pass、释放材质并清理监听。


网络页的「并发数」滑块与标题、「自适应」开关同行，数字跟随滑块下方。代理开关、类型选择与地址输入在同一行对齐；不再显示地址填写说明，地址校验及成组自动保存仍保留。手动范围 1–32，`concurrency` 保留手动值；启用 `adaptive_concurrency` 后禁用滑块，下载调度不使用该手动值。自适应从 4 个并发开始，在 1–32 范围内每秒观察已接收字节、完成数和重试数：有进展时逐步加一，遇到重试或连续三秒无进展时减半，并保留两秒恢复期。降低目标只暂停补充新任务，不中断已开始的传输。取消或失败时释放所有正在等待的下载 Future，保留可续传网络部分文件，清理目标临时副本；运行中任务仍保持启动时的设置快照。

设置外框使用 `vPanelSize` 观察标题和内容的固有尺寸，为外框高度与宽度施加 300ms 缓动；页签、代理展开和文案换行都会重新计算目标高度。不会缩放文字，不观察正在动画的外框以避免自触发循环，原生 dialog 尚未打开时不记录零尺寸。窗口限制仍由 max-height 和内部滚动处理，减少动态效果设置会跳过动画。

关于页的仓库首页和问题反馈页已加入桌面 opener 允许列表，保留微软登录和当前仓库发布页权限。权限配置变更需要重新构建／重启桌面进程才能生效。


### 校验结果复用与发布构建

`verification` 按数据目录共享、按需加载 `cache/verified-files.json`。记录绑定路径、预期哈希与算法、文件大小、纳秒修改时间及创建时间，Unix 另存设备、inode 和 ctime。普通安装／续传只在这些信息一致时跳过内容读取；没有记录、文件变化、记录格式未知或损坏时完整计算哈希。读取文件后的身份／时间需与读取前一致，才能保存记录。复制缓存时检查来源是否保持不变，发生变化则校验临时副本。新下载与续传文件仍须校验通过才能晋升完整缓存。

哈希读取放入有界阻塞线程，一次任务顺序读取文件，避免每个小块都切换异步文件线程；每个数据目录最多 8 个检查同时进行。独立文件／批次结束（含失败与取消）原子保存记录，进程意外退出前尚未保存的记录下次会保守地重算，不把断点数据直接视为已验证。界面「校验修复」通过 `install { repair: true }`，CLI `repair` 通过 `Launcher::repair` 强制绕过记录执行完整校验；普通下载使用 `Launcher::install`。

普通 CI 在 Linux 执行一次前端测试、构建、Rust 格式检查、完整测试和 Clippy，Windows/macOS 只运行文件系统专项测试。测试关闭调试符号生成，桌面端只产出 rlib 及可执行文件，移除未使用的移动端库输出。发布等待标签对应提交的 CI 通过，复用其前端产物，三个原生任务只进行一次 release 编译和打包，不重复检查或构建前端。按 artifact ID 下载时明确设置 `merge-multiple: true`，避免多出 `ci-frontend` 子目录。编译前检查入口资源，编译后执行原生程序 `--verify-frontend` 检查内嵌入口、JS 和 CSS；这个命令在打开窗口和用户数据前退出，无需额外编译。

发布专用 `tauri.release.conf.json` 将 [Tauri beforeBuildCommand](https://v2.tauri.app/reference/config/#beforebuildcommand) 置空，防止重复运行前端构建；本地默认配置仍自动构建前端。标签任务调度默认分支上的同一发布 workflow，使后续标签能访问同一分支的发布缓存；所有源码步骤仍检出并校验标签的确切 SHA，缓存不作为发布依据。Rust 缓存按目标区分并启用 [rust-cache 的 workspace 与失败缓存](https://github.com/Swatinem/rust-cache)，重跑可复用编译结果。保留版本一致性、原生架构、macOS 签名验证、产物完整性和 SHA-256 核验，三个平台齐全后才发布。

性能回归可运行 `cargo test -p nekocrate-core benchmark_verified_cache_reuse -- --ignored --nocapture`：在临时目录创建 2,048 个 64 KiB 文件，分别测量首次校验与重新加载记录后的复用，断言后者不读取任何文件内容；不访问网络或用户游戏目录。
