# 原型架构

## 边界

UI 通过单个带标签的 IPC Request 枚举调用 Rust。所有文件路径、实例 ID、版本解析、凭据及进程生命周期由核心处理。CLI 复用相同核心。前端仅维护视图、当前会话任务和最近 800 条日志。

核心模块：

- `auth`：微软设备授权、Xbox/Minecraft 令牌交换、权益检查与系统凭据存储。
- `skin`：提取 Minecraft 档案中的活动皮肤，限制官方纹理地址、文件大小与 PNG 尺寸，缓存公开纹理；请求不携带账户令牌，不跟随重定向。
- `download`：有界并发、逐来源重试、取消、哈希验证、内容寻址缓存、临时文件提交。
- `minecraft`：官方版本元数据、OS/架构/feature 规则、资源与库安装、原生文件解压、参数展开。
- `java`：运行时发现、主版本检查、Adoptium 下载与归档提取。
- `storage`：数据库保存、路径约束、实例文件复制、账户配置排除。
- `Launcher`：操作协调、隔离实例、账户元信息、游戏进程与日志。

游戏进程使用独立的 `LaunchSession`：微软会话转换为带认证参数的启动身份；没有选中账户时生成固定的 Player 本地身份，不持久化伪账户或调用身份服务。前端与 CLI 复用同一个分支。只有真实访问令牌和刷新令牌进入日志脱敏列表，本地启动的占位值 `0` 不参与替换。

## 数据

```text
<data-root>/
  database.json              设置、实例、公开账户档案；无令牌
  database.json.bak          上一次元数据快照
  launcher.lock              跨进程独占锁
  metadata/                 官方 manifest 与带校验的版本 JSON
  cache/objects/sha1|sha256/ 可验证内容缓存
  cache/skins/              按纹理标识缓存的公开玩家皮肤
  libraries/                共享的依赖（客户端在实例目录内）
  assets/                   资源索引、对象、日志配置
  runtimes/                 托管 Java
  instances/<uuid>/
    .minecraft/             仅托管实例；关联实例的游戏目录留在外部原路径
      saves/ mods/ config/
      versions/<version>/   同一目录可容纳多个版本
        <version>.json      此版本的官方元数据
        <version>.jar       此版本的客户端
        natives/            此版本的原生库
        runtime.json        运行时路径与版本（非凭据）
    launcher-logs/          脱敏的游戏输出
  trash/                    移除的托管实例，或外部实例的关联元信息与日志
```

实例身份使用 UUID，与名称分离。一个实例就是一个 `.minecraft` 游戏目录，包含 `versions[]` 与 `selected_version`；添加版本不创建新的游戏目录。多个版本共用该目录的存档、模组和配置，客户端与原生库按版本分别存放。运行中的实例不可切换版本，也不能同时启动第二个版本。

`game_directory` 为空时使用 `instances/<uuid>/.minecraft`；导入已有目录时保存规范化后的绝对路径，数据目录只保存实例元信息、日志及共享缓存。`Instance::game_dir` 统一决定启动工作目录、`--gameDir`、客户端与原生库路径，安装与目录打开也使用这一位置。导入不遍历复制游戏树、不读取其他启动器凭据；拒绝重复、嵌套关联和与启动器数据目录重叠的路径。原路径不可用时启动、安装、复制会报错，不在原位置自动重建空目录。移除关联实例只归档启动器自己的元信息／日志，原目录保持原处。

实例元数据的可选 `icon` 保存 16 种内置图标的编号，缺失时沿用 UUID 决定的原四款默认图标，兼容已有数据库。`InstanceHeader` 在实例弹窗标题栏提供图标选择、名称原位编辑和目录链接；名称与图标随表单保存，取消不修改实例。目录通过只读 IPC 获取实际路径，点击时复用系统文件管理器打开流程；改名和换图标不会移动游戏目录。

实例顺序直接持久化为数据库 `instances` 数组顺序。拖动图标使用 Pointer Events 与指针捕获，移动超过 6px 才开始排序，支持边缘自动滚动、Esc／失焦取消和 Alt＋左右方向键排序；松手后抑制误触选择。拖拽期间通过 `TransitionGroup` 预览位置，相邻图标以 320ms 先快后慢曲线让位，命中判断使用布局坐标以避免动画造成抖动；开始移动时把指针捕获转移到稳定的滚动容器。拖动预览保留原图标的透明度与发光；松手后以 360ms 动画归位，再交叉淡化到真实图标；保存回滚时从动画当前位置改道。`move_instance` IPC 仅提交来源与目标位置，不覆盖整份实例列表；数据库锁内按 ID 移动，拒绝已删除的来源或目标，允许运行／下载期间排序。保存失败恢复原排列，当前选择、游戏目录、版本状态和游戏进程不变。

CLI 显式复制实例时才复制整个游戏目录和版本列表到新的托管目录，保留已安装状态，资源与依赖继续复用共享缓存；复制过程不跟随符号链接，并排除已知启动器账户文件。导入只关联来源并识别多个独立版本 JSON，首次启动前仍须校验安装。

数据库 schema 3 支持目录关联。schema 1 仍先迁移旧的一对一实例：将 `game/` 改为 `.minecraft/`，把旧版本纳入版本列表，迁移元数据、客户端和原生库；迁移前保存 `database.v1.json`。schema 2 升级时保存 `database.v2.json`，已有托管实例和以前导入的副本不移动、不推断来源；要使用原始目录，需重新添加原路径。旧客户端会拒绝 schema 3，避免忽略关联路径后误用空的托管目录。

账户档案新增可选的 `skin` 元信息（URL、是否纤细手臂），旧账户反序列化默认为空，刷新账户后补齐。前端经 IPC 获取纹理字节，使用 [skinview3d](https://github.com/bs-community/skinview3d) 进行透明背景的 WebGL 渲染，并从同一纹理裁切头像；不开放 WebView 对外纹理请求。切换账户时丢弃过期请求结果，关闭组件释放渲染资源，弹窗打开或窗口不可见时暂停绘制。未登录、无皮肤资料或加载失败时回退到内置的原版 Steve 纹理；加载失败保留重试入口。

皮肤场景使用按需绘制：纹理、尺寸、视角改变时合并到下一显示帧，OrbitControls 惯性未结束时继续更新，静止后停止 WebGL 重绘。隐藏、弹窗与 WebGL 上下文丢失时取消待绘制帧，恢复后补绘；像素比、抗锯齿、灯光、模型与拖动参数保持不变。背景动画独立运行。`rendering.test.mjs` 覆盖静止、合并请求、惯性、暂停恢复与销毁。

主界面使用左上账户卡片、底部主题与实例图标、分体启动按钮。账户卡片打开头像选择弹窗，点击头像选择当前账户，「+」进入添加流程；非当前账户头像独立加载官方皮肤，并忽略已卸载组件的异步结果。登录应用配置归入添加账户流程，保存全局设置时保留最新应用编号。`GlassDialog` 基于原生 `dialog.showModal()` 实现焦点约束和背景隔离，初始焦点放在静态标题上，账户、设置、日志、下载与实例管理复用该弹窗。`VersionMenu` 在启动按钮旁向上展开当前实例版本，尾项进入下载弹窗；菜单独立处理键盘导航、Esc、焦点离开和外部点击收起，切换实例会收起旧菜单，保留版本按钮节点以避免闪烁。五套主题由统一 CSS 变量驱动，主题与当前实例选择在本地持久化。主题图形的可见大小与间距不变，真实透明按钮连续覆盖 36 × 64px（当前主题为 44 × 64px）；命中区不随展开动画移动，按下时捕获指针，松手后提交选择，避免 Safari 失焦收起菜单。主题区域高于实例列，防止选项被后绘制的实例按钮遮挡。默认与最小窗口均为 900 × 600。

`flowGraph.ts` 在整数周期格点上构造蜂巢、大小方块、菱形、三角和八边形／小菱形五种平面铺砌，共享边只保存一次状态。`hexFlow.ts` 保留既有模拟 API，统一使用图中的邻边数量计算转移概率；封闭面识别、容量及染料交换适用于所有图形。`WorldBackdrop` 只将状态写入可见 SVG 路径，不逐帧触发组件重渲染。切换主题时通过组件 key 清理旧动画帧、尺寸监听和可见性监听，再构造新图形。弹窗和菜单不暂停背景；隐藏页面、减少动态效果和高对比模式分别停帧或隐藏装饰。

背景复用连通区域遍历队列、标记及染料来源缓冲区。`flowPainter` 对相同边的多个平铺副本只格式化一次数值，先比较量化后的颜色比例，再生成 CSS 混色字符串；实际 SVG 路径、更新阈值和精度均不变。五套主题各 300 帧的模拟状态与 SVG 属性通过优化前记录的哈希验证，包含减少动态效果及恢复绘制。空实例的主按钮合并右侧菜单区域，直接打开版本下载；已有版本时启动图标与文字成组上移 5px，版本号在整组下方居中。账户栏、启动按钮和上拉菜单共享透明底色，启动按钮悬停与账户栏使用相同透明度。启动区固定外宽，启动／下载状态仅通过内容移位、交叉淡入淡出和版本按钮浮现过渡；子版本名独立做轻微移位与淡化，短暂保存状态不改变按钮透明度。

全局设置标题栏直接展示「通用设置／网络设置」页签，支持方向键、Home／End 切换。初始焦点仍放在静态容器上。通用页提供语言、游戏启动时跟随语言的开关、启动器版本与更新状态，以及启动器目录；网络页包含下载源、并发下载及失败重试；不再展示 Java 检测、自动安装 Java 开关或下载记录入口。打开时从数据库快照建立表单草稿，切页保留草稿，保存时统一校验数值并保留后台的 Java 与登录应用配置；取消不持久化。`GlassSelect` 为语言和下载源复用主题色玻璃菜单；`DownloadSourceSelect` 展示三种来源策略，保留原有来源值；选择项支持方向键、Home／End、Enter、Esc、焦点离开和外部点击，组件卸载时清理监听。菜单悬停只改变文字和光效，不使用渐变填充；版本菜单选中项仅通过文字光效与实心图标标识。


语言支持「跟随系统 / 简体中文 / English」，默认跟随系统。系统首选语言由 Rust `sys-locale` 读取并随快照传入前端；简体中文使用中文，其他语言（包括繁体中文）使用英语。设置中的语言可即时预览，取消恢复已保存语言。文案、菜单、无障碍标签和启动器提示在前端本地化，用户名称、路径和游戏原始日志不翻译。语言标签复用实例字段的 12px 字体与 44px 控件；「启动器版本」使用同样的小标签，当前版本号与「启动器目录」同为 14px。设置页签交叉切换时保留内容区高度；弹窗打开／关闭使用淡化和轻微缩放，关闭完成后退出顶层模态并恢复原焦点，切换到另一弹窗时不会抢走新弹窗焦点。背景动画独立继续运行。

开启「游戏启动时跟随」后，启动前按同一解析规则把 `options.txt` 的 `lang` 设置为 `zh_cn` 或 `en_us`。关闭时不触碰此文件；开启时保留其他选项及换行格式，原子写入并备份为 `options.txt.nekocrate.bak`，内容未变时不轮换备份。旧数据库缺少新增字段时兼容默认设置。 开关通过 `aria-labelledby` 获取名称，文字和整行不代理点击，仅开关本体可切换。

打开设置时从官方仓库 GitHub Releases API 检查更新，识别当前 `dev0.1` 与后续语义版本；开发版接受预发布，稳定版只接受稳定发布，不降级。新版入口按平台打开官方发布的安装包下载地址，缺少对应包时打开该版本发布页，不自动替换运行中的程序。检查失败显示重试入口。

全局设置保存独立于下载任务的忙碌状态，并由数据库锁原子持久化；正在执行的下载保留任务开始时的配置，新任务读取新设置。下载完成只刷新状态，不重置正在编辑的设置、页签或草稿。快照请求采用顺序编号，保存之后到达的旧快照不覆盖新设置；弹窗提交记录所属会话，旧请求不会关闭重新打开的弹窗。

应用图标使用 AI 生成的 Minecraft 像素猫咪盒子、Creeper 与浅浅探头的 Minecraft 猫猫，原图及完整提示词保存在 `app/src/assets/neko-cat.png` 和 `neko-cat.provenance.json`，通过 Tauri icon CLI 生成 PNG / ICO / ICNS。

## 一致性与恢复

元数据操作在互斥锁中执行，先保存候选数据库再更新内存。安装开始先将所选版本的 `installed` 设为 false，全部文件和 Java 就绪后才设为 true，不影响同实例中的其他版本。运行中的实例禁止复制、修改、移除、重装。

下载文件只有在哈希与大小验证通过后才写入缓存/目标；部分文件临时路径在取消或错误后清理。同一缓存对象并发请求串行，缓存复制到目标，避免用户修改目标文件破坏缓存。每个网络来源有独立重试，身份服务请求不走文件镜像。

## 后续扩展点

加载器应在版本解析/安装计划层加入，不在 UI 中拼启动命令。整合包更新应提供独立的文件清单、差异计划和回滚协议。外置认证应实现独立提供方，不改变微软权益验证语义。

本原型未提供任意自定义 JVM 参数和启动前 shell 命令。已有目录导入会识别独立版本 JSON；安装仍从官方版本目录获取并校验元数据，不会将未知自定义版本 JSON 当成可信启动计划。
