# dev0.4 渲染与响应性能记录

2026-10-23，在 M4 Pro / macOS 15.7.7 的本地 `cargo ui` 中检查。保持原有显示帧率、设备像素比、五套几何图案、300 ms 马尔可夫转移、平滑参数和颜色扩散；弹窗打开时背景继续运动。窗口不可见时的空闲采样不用于证明优化效果。

## 实际热点

最初的 Canvas 版本虽然去掉 SVG 节点更新，仍逐帧填充和描边数百条路径，并将完整图块复制到窗口。窗口可见时，`sample` 在 Graphics and Media 中捕获到 `RemoteDisplayListRecorder::fillPath`、`strokeLine`、`WebCore::Path::platformPath`、Core Animation 的绘图队列及 Metal 提交。皮肤的 WebGL 队列在这段采样中等待，没有持续重绘。

直接绘制可见路径只能减少部分工作。最终改为常驻 GPU 的有序几何：填色与描边在同一 mesh 中，按完整图块实例化，每帧一次属性缓冲上传、一次绘制调用。保持逐路径的 source-over 叠加顺序，不把相交边合并成一条路径。所有不可见格子的状态仍完整推进，由 GPU 裁切呈现副本。

新采样中原来的 Core Graphics 路径转换与逐路径提交热点消失。前端随后出现的 `toFixed` / 字符串数值解析热点也被移除：普通值直接数值舍入，可能受浮点乘法舍入影响的半边界仍回退到原转换，测试覆盖每个相关边界及其相邻浮点数。

## 本机短时观测

通过进程累计 CPU 时间差除以可见窗口采样时长，得到 Graphics and Media 的单核百分比。每段 20–26 秒，开发模式；这是本机短时观测，不是跨平台性能承诺。

| 实现 | 平均 CPU |
| --- | ---: |
| 完整 Canvas 图块重画、复制 | 17.07% |
| Canvas 仅画可见路径，两轮 | 13.52%、14.36% |
| GPU 批量绘制，初轮 | 6.03% |
| 最终单次实例化绘制 | 6.41% |

独立合成层的尝试没有稳定收益，未保留。GPU 利用率没有取得可靠的对应测量，不能将上述 CPU 降幅当成 GPU 降幅。背景仍持续变化，窗口合成与模拟仍有开销；未使用限帧、降低 DPR、关闭动效或简化图案。

## 视觉和行为校验

- 五套图形逐帧与优化前 SVG 绘制器比较线宽、透明度、混色比例及模拟哈希。
- 用独立的原 SVG 栅格结果比较实际 GLSL 输出，覆盖 DPR 1 / 1.25 / 2、平移中点及周期两侧，共 60 个画面。使用相同的模拟种子和状态；跨渲染器抗锯齿存在边缘像素差异，不能称为逐像素相同。本机平均 RGB 通道误差不超过 0.64 / 255，单通道最大误差 17 / 255。
- GPU 资源只在初始化、尺寸变化和上下文恢复时重新配置；逐帧测试限制为一次属性上传和一次实例化绘制。
- 实际 Vue 组件测试覆盖隐藏恢复、减少动效、DPR 改变、上下文丢失、恢复失败后的 Canvas 回退及卸载清理。

可选离屏复现不启动浏览器、不访问用户实例，不增加应用或 CI 的原生依赖：在独立目录 `.runtime/render-tools` 安装 `@napi-rs/canvas@0.1.80`、`@resvg/resvg-js@2.6.2`、`gl@8.1.6`（后者可能需要本机原生编译工具），然后在仓库根目录运行：

```sh
node --experimental-strip-types scripts/compare_flow_rendering.mjs
```

输出图像与统计保存在 `.runtime/flow-reference`。脚本前两个参数可分别指定输出目录、独立依赖目录。

## 其他已验证的热点

下载列表此前在每个文件状态变化时扫描、分组整个文件表。现在按阶段维护稳定分区索引，单次变更与可见行定位使用 O(log n) 查询，仍只展示 10 行、正在下载的文件置顶且同组顺序不变。30,000 文件、1,000 次状态变化的本地 Vue 回放由约 4.9 秒降至约 6 毫秒；这是合成列表回放，不是实际网络下载耗时。

日志原先在达到 800 行后通过深层响应式数组移动所有索引。现在保留相同顺序、截断条件、复制和清空行为，每次追加只发一次响应式通知。5000 次合成追加的本地回放由约 1.4 秒降至约 1 毫秒；不丢弃或合并日志事件。
